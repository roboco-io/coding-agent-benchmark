# gpt-6.1-sol 세션 시간 증가 원인 분석 (2026-10-03)

## 질문

gpt-6.1-sol의 완주 세션 시간(Codex EXP-033 6.2-9.8분, pi EXP-034 8.3-9.2분)은 gpt-6-sol(Codex EXP-027 4.8-5.2분, pi EXP-030 4.2-5.6분)의 약 2배였다. 이 시간이 어디서 늘었는지 두 하네스의 실행 이력(세션 jsonl)으로 분해한다.

## 방법

- `timeline.py`가 세션 기록을 시간순으로 읽고, 직전 이벤트부터 다음 이벤트까지의 구간을 다음 이벤트 종류로 귀속한다. 다음 이벤트가 모델 산출물(도구 호출·reasoning·메시지)이면 **모델 대기 시간**, 도구 결과면 **도구 실행 시간**이다.
- 원자료: `~/ralph-exp027`·`~/ralph-exp033`의 Codex rollout, `~/ralph-exp030`·`~/ralph-exp034`의 pi 세션(리포의 각 실험 `runs/sessions.tar.gz`와 같은 파일).
- 시점 교락을 줄이기 위해 2026-10-03 09:19-09:23에 같은 Codex 격리 설정(CLI 0.160.0, effort medium)으로 두 모델에 같은 단일 요청(약 150줄 TypeScript 모듈 작성, 도구 사용 금지)을 번갈아 3회씩 보냈다(`probe.csv`).

## 결과

### 1. 늘어난 것은 모델 대기 시간이다

| 조건 | 세션(초) | 모델 대기(초) | 도구 실행(초) | 모델 호출 수 | 호출당 대기(초) | output | 모델 대기 1초당 output |
|---|---|---|---|---|---|---|---|
| Codex × gpt-6-sol (EXP-027) | 284-311 | 244-255 | 40-55 | 26-35 | 7.3-9.5 | 10.4-11.0K | 42-45 |
| Codex × gpt-6.1-sol (EXP-033) | 371-587 | 344-557 | 27-39 | 21-31 | 16.4-23.0 | 10.0-16.2K | 29-30 |
| pi × gpt-6-sol (EXP-030) | 251-330 | 215-293 | 36-37 | 31-35 | 6.7-8.4 | 7.0-8.6K | 26-39 |
| pi × gpt-6.1-sol (EXP-034) | 495-547 | 442-488 | 43-59 | 29-34 | 14.3-15.2 | 12.5-13.3K | 27-28 |

- 도구 실행 시간(npm 설치·빌드·Hurl 실행 등)은 두 모델이 비슷한 범위였다. 세션 증가분은 거의 전부 모델 대기 시간에서 나왔다.
- 모델 호출 수도 비슷했다. 에이전트가 더 많이 왕복해서가 아니라 **호출 한 번당 대기 시간이 약 2배**가 되었다.

### 2. 호출당 대기 증가는 생성 속도 저하와 output 증가가 겹친 결과다

- Codex에서는 모델 대기 1초당 output이 42-45 토큰에서 29-30 토큰으로 줄었다(약 30% 감소). run당 output은 범위가 겹친다.
- pi에서는 run당 output이 7.0-8.6K에서 12.5-13.3K로 약 1.6배 늘었고, 1초당 output은 비슷하거나 낮았다.
- reasoning 토큰은 두 모델 모두 run당 1-2K 수준이라 대기 증가를 설명하지 못한다.

### 3. 같은 시각에 번갈아 보낸 요청에서도 gpt-6.1-sol이 느렸다

| 모델 | 요청당 시간(초) | output | 초당 output |
|---|---|---|---|
| gpt-6-sol | 32.1-38.4 | 1,183-1,413 | 36.6-37.6 |
| gpt-6.1-sol | 45.7-53.7 | 1,386-1,623 | 28.6-30.3 |

- 같은 요청에서 gpt-6.1-sol은 약 1.4배 오래 걸렸다. output이 10-17% 많았고 초당 output이 약 20% 낮았다.
- 따라서 측정 날짜(서버 부하)만으로는 설명되지 않는다. 모델 또는 그 모델의 서빙 경로가 이 시점에 더 많이, 더 느리게 생성한 것이 주원인이다.

### 4. 클라이언트 버전은 주원인이 아니다

- pi는 EXP-030과 EXP-034 모두 같은 버전(0.87.1)이었는데도 세션이 약 2배가 되었다.
- Codex는 버전이 달랐지만(EXP-027 0.155.1·0.156.1, EXP-033 0.160.0) pi와 같은 방향·비슷한 크기로 늘었다.

## 한계

- 실험 run의 2배와 동시 비교의 1.4배 사이 차이는 에이전트 작업에서 output이 더 늘어난 효과(pi에서 약 1.6배)와 측정일 서버 상태가 섞인 것으로 보이며, 둘을 분리하지 못했다.
- 동시 비교는 단일 요청 3회씩이다. 에이전트 루프 전체를 같은 날 번갈아 재측정하지는 않았다.
- 서빙 측 사정(배포 초기 용량, 라우팅)이 원인인지 모델 자체의 생성 특성인지는 외부에서 구분할 수 없다. 시간이 지나면 달라질 수 있다.
- 구간 귀속은 기록 시각 기준 근사다. 모델 대기에는 첫 토큰 대기·입력 처리·네트워크 시간이 함께 들어 있다.
