# EXP-024: Fable 5.1·Astra 실무 조합 비교 파일럿

> 상태: **설계 작성·Phase 0 차단, 본 실험 0/24회** (2026-09-21).
> [설계 템플릿](../../templates/experiment-readme.md)과 [품질 규칙](../../docs/experiment-quality-rules.md)을 적용한다.
> 사용자 확정: Claude Code + Fable 5.1 / Codex + Astra, **기존 구독만 사용**, 24회, run당 30분·최대 10 iteration, 한도 도달 시 중단.

## 가설

- 코드: P-01 (탐색). 동일 과제·품질·시간 예산에서 두 조합의 작업별 합격률과 시간·복구 양상을 관측한다.
- 질문 유형: 실무 조합 효율. 모델 또는 하네스 단독 효과 분리는 목적이 아니다.
- 선택 질문: 신규 구현·버그 수정·기능 추가·DB 마이그레이션에 어느 조합이 적합한가?
- 주 지표: 30분 이내 최종 독립 채점 합격률. 한 유형당 한 과제·3회이므로 순위 확정이나 유의성 주장을 하지 않는다.
- 보조 지표: 첫 iteration 합격, 후속 iteration 추가 합격, 실패·채점·복구 포함 시간, usage, 사람의 개입·검토 시간.
- 실무 차이 탐색 기준: 합격 건수가 같을 때 성공 run 중앙 시간의 20% 차이를 후속 확증 후보로 표시한다. 확정 우위 판정은 하지 않는다.

## 과제·완료 기준

공통 스택은 TypeScript + Fastify + Prisma + SQLite, 공통 언어 EN이다. 다음 네 과제는 독립 시작 상태를 쓴다. 다른 run의 산출물을 다음 run의 입력으로 넘기지 않는다.

| ID | 작업 | 명세·완료 기준 |
|---|---|---|
| build | 신규 구현 | 빈 저장소에서 RealWorld API 구현. 고정 Hurl 13파일·154요청 및 인증·권한·경계 조건의 독립 채점 통과. |
| bug | 버그 수정 | 정상 기준 구현에 타 사용자 댓글 삭제를 허용하는 결함을 주입. 작성자만 삭제 가능, 다른 사용자 403, 무인증 401, 기존 댓글·아티클 API 회귀 통과. |
| feature | 기능 추가 | 기준 구현에 `GET /api/articles?titleContains=` 필터 추가. ASCII 대소문자 무시 부분 일치, 빈 문자열은 필터 없음, 기존 tag/author/favorited와 AND 결합, 필터 후 articlesCount 및 pagination 검증. |
| migration | DB 마이그레이션 | 기존 사용자 데이터에 선택적 `displayName` 추가. 기존 사용자 값 null·로그인 유지, 프로필 응답/본인 수정 지원, null 또는 1–80자 허용, 빈 문자열·초과 길이 422. 데이터 보존 및 반복 migration의 안전성 검증. |

- 명세에 없는 동작을 숨긴 테스트로 요구하지 않는다. 학습용 공개 테스트와 최종 채점을 분리하고 최종 채점 내용은 에이전트에 노출하지 않는다.
- 초기 코드·DB·정답/오답 fixture·프롬프트·채점 해시와 예상 assertion 수는 **아직 미고정**이다. 해당 자산 검증 전 본 실험을 시작하지 않는다.
- 과거 Hurl 사본은 `~/ralph-exp021/harness-hurl`, `~/ralph-exp023/harness-hurl`에 존재함을 확인했다. 저장소 정본과 동일하다고 아직 검증하지 않았다.
- 기존 모델 생성물을 기준 구현으로 채택할 경우 출처와 편향 가능성을 기록하고 모든 조합에 동일 상태를 제공한다.

## 환경·비교 범위

- 각 run은 초기 코드·DB·세션을 초기화하고 다른 run의 파일·대화·메모리를 읽지 못하게 한다.
- 공통 실행기가 별도 작업 환경을 만들고 채점은 해당 에이전트의 쓰기 권한 밖에서 수행해야 한다. 보호된 채점·공통 runner는 아직 구현 전이다.
- OS·Node·npm·Hurl·lockfile·CLI 및 실제 노출 지침·스킬·MCP·권한을 manifest에 고정한다. 인증정보는 저장소에 넣지 않는다.
- Docker CLI는 있으나 daemon은 현재 실행되지 않는다. 격리 환경은 준비되지 않았다.
- Claude smoke는 restricted·도구 없음·MCP 없음·설정 소스 없음 조건이다. **실제 코딩 환경의 격리 검증은 아니다.** 기본 내장 스킬은 smoke init에 보인다.
- Codex smoke는 사용자 config/rules 무시, read-only·ephemeral 조건이다. JSON stdout만으로 served model identity를 검증할 수 없어 실행 전 추가 계측이 필요하다.
- 서버 캐시와 구독 공유 한도는 완전 통제할 수 없다. 두 조합을 가까운 시점에 교차 실행하고 확인 가능한 캐시·한도 이벤트를 기록한다.
- 과거 기준선은 참고용이다. 비교는 이번 파일럿의 동시기 두 조합으로 수행한다.

## 반복·실행 순서·예산

- 4개 과제 × 2조합 × 과제별 3회 = 24회. 한 유형의 반복을 독립 과제 3개로 세지 않는다.
- `schedule.json`: seed 20260921, 과제·반복 블록 내 두 조건 연속 실행, 전체 선행 순서 6:6 균형.
- run당 1,800초는 에이전트·공개 피드백 채점·최종 채점까지 포함한다. 최대 10 iteration. 채점까지 완료하지 못하면 시간 초과다.
- 총 계획 시간 상한은 run 시간 합 12시간이며 환경 준비·Phase 0는 별도 기록한다.
- 기존 구독만 사용한다. API 키·커스텀 endpoint·라우터를 사용하지 않는다. 추가 유료 사용(overage)은 허용하지 않는다. 구독 자동 추가 사용 비활성 확인 전 본 실행 금지.
- 한도 도달 시 전체 캠페인을 중단한다. 미실행 run은 실패 0점으로 채우지 않고 미실행으로 보고한다. 자동 재시작·다른 계정·API·모델 전환은 하지 않는다.
- 무개입 트랙: 사람의 코드 수정·프롬프트 보정은 금지한다. 환경 준비·사후 검토 시간은 실행 시간과 별도로 기록한다.
- 장애·시간 초과·모델 전환·채점 실패는 기존 기록을 덮어쓰지 않는다. benchmark 시작 뒤 발생한 장애는 전체 결과에 포함하고 유효 모델 조건 분석은 별도 제시한다.

## Ralph 정책

- 각 iteration은 새 세션으로 시작한다. 같은 run의 코드·DB·Git 이력은 유지하되 채점용 DB는 독립 초기화한다.
- 프롬프트는 고정한다. 다음 iteration에 공개 테스트 실패 요약만 전달하며 숨김 채점의 세부 결과는 전달하지 않는다.
- `.ralph-done`은 요청 신호다. 에이전트 선언이나 정상 CLI 종료만으로 통과 처리하지 않는다.
- 공개 게이트 통과 시 최종 보호 채점 후 run을 끝낸다. 최종 실패 후 숨김 테스트 기반 재시도는 허용하지 않는다.
- 최초/최종 합격률의 차이는 이 정책 아래 추가 시도의 관측 이득이다. Ralph 대 다른 전략의 인과 효과로 표현하지 않는다.

## 계측·분석 계획

- Claude: assistant message.id 중복 제거. Codex: 요청별 usage 또는 turn 증분과 rollout 누계 의미를 검증한 전용 어댑터 필요. v2 Claude 집계기에 Codex 로그를 넣지 않는다.
- 원자료에 CLI stdout/stderr·요청/세션 ID·실제 모델·버전·종료 코드·시각·usage·채점 결과·artifact commit·개입/장애를 보관한다.
- reasoning 포함 관계와 캐시 필드를 분리하고 미측정을 0으로 채우지 않는다. 모든 실패·재시도·복구 호출을 포함한다.
- 비용은 `subscription_unallocated`: run별 실제 비용 미측정. CLI의 목록 단가 추정은 참고치이며 실제 지출이 아니다. 비용 순위는 산출하지 않는다.
- 분석은 과제별 대응 비교, 합격 건수/시도 수와 신뢰구간, 성공 조건부 시간 및 전체 소요 시간을 함께 제시한다. 서로 다른 작업 유형을 단순 평균해 보편 순위를 만들지 않는다.
- 준비·검토 시간은 관리자의 이벤트 기록으로 측정한다. 측정하지 않은 과거 사람 작업 시간은 추정해 채우지 않는다.
