## usage·집계 검증

- 집계기: `usage_pi.py`(이번 실험 신규). assistant 메시지는 `responseId`로 중복 제거하고 같은 ID에 다른 usage면 오류로 중단한다. `type:"usage"` 엔트리도 포함하도록 작성했으나 이번 실험에서는 0건이었다.
- 전 run 중복 0건·usage 누락 0건. 사전 검증으로 스모크 세션 파일을 복제해 중복 2건이 제외되는 것을 확인했다.
- pi usage 의미: `input`은 비캐시 입력, `cacheRead`·`cacheWrite`는 별도, `reasoning`은 `output`에 포함(`totalTokens` 검산).
- 캐시 기록 양상: Moonshot은 `cacheWrite`가 기록되고 DashScope·DeepSeek는 `cacheWrite` 0·`cacheRead`만 기록됐다. 제공자별 응답 필드 차이이므로 대리지표를 제공자 간에 직접 비교하지 않는다.
- 응답 모델: 전 assistant 메시지의 `provider/model`이 조건과 일치(kimi 109, qwen 219, flash 109건). thinking 수준은 run 내내 kimi `high`, qwen `medium`, flash `high`.

## 관측과 설명

- 관측: pi는 세 모델 모두에서 변환 계층 없이 OpenAI 호환 엔드포인트로 도구 호출을 문제없이 수행했다. 하네스 트러블슈팅은 0건이었다.
- 관측: 에이전트들은 PATH의 `hurl`이 npm `@hurl/cli`라는 사실을 스스로 발견해 자기 스크립트에서 Homebrew Hurl을 찾도록 우회했다(kimi-en-1 등). 판정은 하네스 채점기(절대 경로)로 했으므로 영향은 없다.
- 설명 가설(미검증): qwen의 세션 시간이 긴 것은 응답 1건당 지연이 큰 제공자·모델 특성일 수 있다. 요청별 지연을 계측하지 않아 확인하지 않았다.
