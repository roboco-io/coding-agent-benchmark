## 모델 유지·노출 설정

- 응답 모델: 세션 assistant 메시지의 `model`이 k31pro run은 전수 `kimi-k3.1-pro`, k31hs run은 전수 `kimi-k3.1-pro-highspeed`다. Claude Code는 모르는 모델 ID에 `[claude-code:unrecognized_model]` 안내를 출력했고, 스킬 기본값대로 미인식 모델 200k 창 제한 해제 env를 넣었다. 최대 프롬프트는 79.1K로 200k 아래였다.
- 노출: 격리 `CLAUDE_CONFIG_DIR`, run별 세션 보관. 에이전트 도구 호출에서 하네스 경로(`measure.sh`·`metrics`·다른 run 등)를 참조한 건수는 0이다. 세션 기록에 나타나는 `claude-config` 경로는 Claude Code가 남긴 출력 파일 경로(메타데이터)다.
- 서브에이전트 호출은 재실행 6 run에서 0건이었다(폐기 run에서는 1건).

## 이탈·특이 사항

- **D-1 첫 기동 중단·재실행**: 14:37 첫 기동의 k31pro-en-1을 14:43 사용자의 과금 이상 문의로 중단했다(실험 품질 규칙: 이상 징후 시 조사 전 중단). 중단 시점까지 API 오류는 0이었고 커밋 2개가 있었다. 산출물·세션·로그는 `aborted-k31pro-en-1/`로 옮겨 판정에서 제외하고([runs/aborted-k31pro-en-1.tar.gz](runs/aborted-k31pro-en-1.tar.gz)), 잔액 대조로 과금이 공개 단가 환산과 맞음을 확인한 뒤 15:41 처음부터 재실행했다. 그 앞의 첫 smoke는 계정 잔액 부족(`HTTP 429`, 잔액 $0.03)으로 FAIL했고, 충전 후 재실행에서 PASS했다.
- **D-2 정체 감시 종료 4회(3 run)**: 원인은 두 가지다.
  - 완료 후 백그라운드 서버 잔존(k31pro-en-1, k31hs-en-2): 에이전트가 `run_in_background`로 `PORT=8000 npm run dev`를 띄워 자체 검증하고 `.ralph-done`·커밋·최종 요약까지 마친 뒤 서버를 끄지 않았다. `claude -p`가 반환되지 않아 300초 뒤 정체 종료됐다. 작업은 끝난 상태였으므로 판정에는 영향이 없고 실행 시간만 약 5분 늘었다.
  - 포트 8000 가정 대기 루프(k31pro-en-3 iter 1·2, k31hs-en-3 iter 1): 에이전트가 `PORT` 없이 서버를 백그라운드로 띄워 하네스가 주입한 빈 포트로 서버가 떴는데, 포그라운드로 `until curl … localhost:8000 …; do sleep …; done`을 실행해 끝나지 않았다. 산출물 쪽 결함이며(2026-10-10 규칙), k31pro-en-3은 이 때문에 상한 안에 완료를 선언하지 못했다. k31hs-en-3은 iteration 2에서 백그라운드 작업을 정리(`TaskStop`)하고 완주했다.
  - 같은 모델의 pi run(EXP-051) 6개에서는 정체가 없었다.
- **D-3 비용 가드 과대 추정**: 가드의 대화 기록 바이트 하한(3바이트=1토큰)이 제공자 보고 프롬프트보다 약 50% 커서(예: 346KB → 115K 추정, 보고 76.6K) 차이를 응답마다 입력 단가로 더했다. 재실행 6 run 가드 누계 약 $13.5는 실제 차감 $5.77의 약 2.3배다. 사용자 결정으로 설정을 바꾸지 않았고 상한에 닿은 run은 없었다. 보수적 추정이라 안전 쪽 오차이지만, Kimi 토크나이저처럼 바이트당 토큰이 적은 모델에서는 상한 조기 도달로 run이 보류될 수 있다.
