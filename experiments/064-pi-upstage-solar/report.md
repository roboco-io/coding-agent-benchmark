참고로 내린 격리 en-1·2·3은 모두 iteration 1에 완주했고 스로틀링 제외 시간은 4:06, 7:04, 7:38(기록값 4:18, 10:25, 12:03)이었으며, 429는 4·62·77건, 스로틀링 대기는 12·201·265초였다. 정가 기준 추정 비용은 $0.05–0.12였다. 세 run 모두 에이전트가 상위 하네스 디렉터리를 탐색하려 했고 격리가 이를 거부했다(D-11). 이 세 run의 값은 표와 아카이브에 남기되 공개 중앙값·범위에 넣지 않는다.

격리 전에 실행한 비격리 4 run도 공개 지표에서 뺐다. en-1은 사용자가 계정 한도 영향을 이유로 제외했다(D-7). en-3은 하네스와 직전 run 코드를 읽었고(D-6), 대체 run en-4는 하네스 밖으로 옮겨 둔 en-1 코드를 찾아 복사해 무효다(D-8). en-2는 유효한 독립 시행(7:00)이지만 비격리 조건이라 참고값으로만 둔다. 이 모델은 빈 리포에서 상위 디렉터리를 적극적으로 탐색하므로, 이 모델의 시간·토큰은 격리 조건에서 측정한 값만 독립 시행으로 본다. 격리 조건은 다른 pi 실험(비격리)과 작업 환경이 다르다(`/bin/ps` 실행 불가 등, D-11). 이 모델은 2026-11-30에 종료되고 정식 Mini 4.5가 2026-12-01에 출시될 예정이다.

### 429 스로틀링 원인에 대한 확인 결과 (D-13)

phase6 실행 전 탐침 요청은 200을 반환했고 응답 헤더에 한도가 있었다. `x-upstage-ratelimit-limit-requests`는 분당 4,000건, `x-upstage-ratelimit-limit-tokens`는 분당 1,500,000토큰(Mini 기준, `solar-pro-4-contributor`는 3,000,000)이다. 요청 수는 run 전체가 129회 이하라 분당 요청 한도에는 한참 못 미친다. 토큰 한도는 근접 가능성이 있다. 성공한 요청의 `input + cacheRead` 토큰을 60초 이동 창으로 합산한 최댓값은 참고 en-1·2·3이 1.29M·1.34M·1.54M, 공개 en-4가 1.47M(429 0건), en-5가 2.50M이다. Pro 4 run은 1.28M–1.78M이었고 한도가 3M이며 429가 0건이었다. 따라서 Mini의 429는 분당 토큰 한도(TPM) 근처의 스로틀링일 가능성이 있다. 다만 이 추정은 확정되지 않았다. 429가 난 시점의 직전 60초 성공 토큰 합은 en-1·2·3에서 대부분 0.7M–1.47M으로 1.5M 미만이었고, en-5는 합이 1.5M을 넘긴 구간이 실행 212초부터 있었는데 첫 429는 324초에 나왔다. 실패한 요청이 한도에 어떻게 계산되는지, 입력·출력·캐시 토큰 중 무엇을 합산하는지는 확인하지 못했다. Upstage 오류 메시지는 "API request limit"이며 한도가 약정 금액(commitment tier)에 따라 정해진다고 안내한다. 429 없이 Mini를 측정하려면 Upstage에 TPM 상향을 요청해야 할 가능성이 크고, 실제 한도 기준은 Upstage에 확인이 필요하다.

pi 0.87.1에서 Upstage Solar Mini 4.5 Preview(공개 격리 2 run), Solar Pro 4, Solar Pro 4 Contributor는 모두 이 과제를 완주했다. 실험 후 사용자는 이후 Solar Pro 4 실험을 `solar-pro-4-contributor`로만 실행하고 비용은 `solar-pro-4` 단가로 공개하도록 정했다(2026-11-24). 따라서 Pro 4 계열의 후속 결과는 contributor 변형의 결과이며, 일반 모델과의 성능 동등성은 이 실험에서 확인되지 않은 전제로 남는다. 후속 과제는 2026-12-01 출시 예정인 정식 Mini 4.5 측정이며, 이 측정에서는 Upstage의 분당 토큰 한도(Mini 1.5M)에 걸리지 않도록 한도 상향을 먼저 요청하는 것이 필요하다.
